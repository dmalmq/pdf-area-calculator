## Context

The target is `C:/Repositories/pdf-area-calculator`, an Electron 39 + React 19 + TypeScript desktop product for opening a vector floor-plan PDF, defining facilities, setting per-page scale, drawing facility/store polygons, editing labels and legends, then saving a project or generating an annotated PDF report. Feature growth has accumulated into one always-visible toolbar with seven control groups and a fixed three-column `320px | canvas | 300px` shell; at the default 1200×820 window this compresses the primary canvas while secondary settings remain permanently visible. The redesign must preserve the Zustand domain model, project-file compatibility, PDF canvas interactions, and report pipeline while making the workflow feel focused, modern, trustworthy, and premium.

## Approach

Approved direction: a **Refined Three-Pane** desktop workspace in a **Mineral + Pine** light visual language, Japanese-first, mixed-user guidance, WCAG AA, and core safety only. Full design record: `docs/superpowers/specs/2026-07-10-ui-ux-redesign-design.md`. Preserve `areaStore` domain actions, `ProjectFile` shape/version, `AppApi`, geometry helpers, the `PdfStage` pointer/render engine, and the report pipeline unchanged; recompose presentation and add a thin safety layer. No new dependency; no React/Zustand/Electron/CSS-stack migration; do not split the `PdfStage` FSM.

Steps are ordered so the tree builds and `npx vitest run` stays green after each phase.

## Assumptions & contingencies

- Optimize for mixed professional users: frequent users retain direct tools and shortcuts, while occasional users get clear task sequencing and contextual guidance without a blocking wizard.
- Make visible UI copy Japanese-first and eliminate the current Japanese/English terminology mixture. Keep technical units and universally understood file extensions as-is; do not add a locale framework or language toggle.
- Include core safety, not a full recovery subsystem: dirty-document guarding, destructive-action confirmation, and bounded in-session undo. Autosave, crash recovery, persistent history, and multi-step project versioning remain excluded because the user selected the smaller safety scope.
- Keep the product a desktop single-workspace application. At narrower supported widths, move secondary inspectors into drawers or tabs rather than hiding core functionality.
- Light mode only. This desktop tool ships one fixed Mineral + Pine light theme; no dark mode or theme toggle is added. Contingency: if a dark variant is later required, the semantic `:root` tokens are the single swap point.
- Deletion keeps BOTH a confirm dialog and one-step undo (the approved workflow), not one or the other. Every delete path (keyboard `Delete`, inspector Delete) routes through the same App confirm + undo flow.
- Canvas overlay draw colors and the `PdfStage` pointer/render engine are left byte-for-byte unchanged to preserve on-canvas/export annotation parity; only surrounding HTML chrome is restyled.
- `aggregate` stays exported from the store (still unit-tested) even though the redesigned Sidebar preview uses `reportBy*`; removing it is avoidable churn.
- The unscaled-report guard keeps the existing native `window.confirm`; only replacement/delete/shortcuts move to `ModalDialog`.
- Contingency — dirty fingerprint cost: `selectIsDirty` re-serializes the persisted slice on store change. Floor-plan projects are small, so this is fine; if pan/drag re-renders show jank, memoize on the persisted slices or fall back to a per-action dirty flag (same public `selectIsDirty` surface).
- Contingency — narrow-window inspector: the drawer uses the `inert` attribute on the background (React 19 + Electron 39 Chromium support it). If `inert` misbehaves, trap focus within the drawer and set `aria-hidden` on the background instead.
